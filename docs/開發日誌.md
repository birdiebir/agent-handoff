## 2026-10-21（初版到審查修正）

### 技術歷程摘要
- 第一階段：三家對話紀錄解析、最近對話清單、接力卡自動產生、claude／codex／agy 三支 adapter、Codex 原生匯入（app-server，只勾 SESSIONS）、`--dry-run`。stdout 只放最後一行 JSON（ASCII 跳脫），說明走 stderr。
- 第二階段：SessionStart hook 登記「Windows Terminal 分頁 -> 對話」；UserPromptSubmit hook 攔截 `/handoff`，本機規劃並用 `wt.exe -w 0 new-tab`（`-EncodedCommand`）開新分頁，不經過模型；`install/install.py` 備份後只加／只移除自己的 hook。
- 第三階段：Codex 同一支 hook 腳本（`--cli codex`）；agy 沒有可攔截提示的 hook，改裝 skill。
- 審查修正：非互動對話（`claude -p`、`codex exec`）不登記；同資料夾 24 小時內有多段互動對話時不猜；Codex 匯入在 hook 路徑改用較短逾時；啟動失敗不留接手標記；接手標記依 Claude session 分開存；agy 工作關鍵字檢查；install 的 hook 指令尾加 `|| true`（Codex 的 `commandWindows` 因 PowerShell 5.1 不支援 `||` 除外）。

### 踩坑與解法
- PowerShell 5.1 轉手 stdin 會加 BOM、轉手 stdout 會被主控台編碼弄壞：hook 讀 stdin 用 `utf-8-sig`，輸出一律 ASCII JSON。
- Bash heredoc 會吃反斜線，含 Windows 路徑的檔案改用編輯工具寫。
- 在 Claude 分頁裡跑 `claude -p` 也會觸發 SessionStart 登記，所以要判斷 entrypoint 排除非互動對話。
